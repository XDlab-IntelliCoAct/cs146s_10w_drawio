# HW6：系统测试与安全验证

**安排：W6。** 在 HW5 已有的检查核心、CLI、CI 和最小界面基础上，创建 `hw06/quality` 分支继续开发。学习顺序见[W6](../weeks/week06.md)。

## 本次作业要解决的问题

前几周的测试主要伴随单项功能编写。本周需要检查这些功能组合后是否仍然可靠：复杂图表能否正确解析，报告和界面是否一致，异常输入是否得到明确处理，文件是否受到保护。你将建立分层测试，验证安全限制，并通过引入已知缺陷检验测试是否有效。

## 实现步骤

### 1. 建立需求—风险—测试矩阵

先列出已有需求及可能出错的情形，再为每项情形选择输入、预期结果和测试层次，形成需求—风险—测试矩阵。测试按以下四层组织：

- 单元测试：检查名称、图元角色、端点、配置和问题标识的计算；
- 模块集成测试：检查解析、多页数据转换、规则执行和报告生成能否配合工作；
- CLI 子进程测试：检查标准输出、标准错误、退出码和文件操作；
- 浏览器测试：检查导入、运行检查、显示结果和修改后重查。

说明每层测试负责回答什么问题。例如，名称是否为空适合直接测试规则，退出码必须启动实际子进程验证，标签是否作为安全文本显示则需要在浏览器中检查。根据这些职责选择输入和断言。

### 2. 扩展结构案例

先使用课程中的 `grouped`、`multi-page`、`compressed`、`html-label`、`invalid` 图表，再自行增加案例，覆盖同页重复 ID、多页相同 ID、同一图元触发多条规则、空文件和空页面。

对于压缩页面，核对解压和规范化前后表示的页面、节点及连接相同。如果应用导入器拒绝或修复了输入，直接调用数据适配和检查函数测试，并分别记录两种调用方式的处理结果。

将同一份固定输入分别交给共享核心、CLI 和开发环境中的检查界面，排除生成时间等元数据后核对问题与统计。输入超限等异常可以直接测试适配器；完整用户流程则在浏览器中验证。

### 3. 实现性质与变形测试

普通案例测试逐项检查预期结果，性质与变形测试则检查一类输入共同满足的关系。至少实现以下五项，并说明每项关系成立的条件：

1. 图元排列变化不改变问题集合；
2. 坐标平移不改变结构检查；
3. 修改一页不影响另一页结果；
4. 为缺名步骤补充名称，对应问题消失；
5. 重复检查不修改输入。

比较语义结果时排除生成时间，用同一套配置。修改会影响连接或角色时，先写清预期变化。

### 4. 验证输入与文件安全

按[共同限制](../docs/contracts.md)检查文件不超过 2 MiB、页面不超过 20 页、图元不超过 10,000 个，以及解压内容的 8 MiB 上限。为每项限制分别测试上限内和刚超过上限的输入。

- 外部实体或 DTD 被拒绝，检查过程不发外部请求。
- text-safety 的标签按文字呈现，不能执行其中脚本。
- CLI 拒绝输出覆盖输入；已有报告写失败后保留原内容。
- 对工作目录外的显式输出做预览，核对绝对路径与实际输出一致。
- 检查日志只包含必要诊断，不包含正文、密钥和环境配置。
- 对当前依赖开展一次安全审查；逐项核对告警涉及的功能是否被本项目实际使用，以及触发条件是否成立。

[安全输入生成器](../tools/make_safety_cases.py)只在指定本地目录生成数据：

```powershell
python tools/make_safety_cases.py --output .runtime/safety-inputs
```

此命令在课程根目录执行，再复制所需输入到产品本地测试目录。生成的大型案例不提交进产品仓库。

### 5. 检查测试是否能发现缺陷

使用已有测试进行三种[缺陷实验](../materials/labs/mutation-lab.md)：故意混淆页面内的图元 ID、漏判空白名称、将未知计数当成零。先预测哪项测试应当失败，再执行并核对。

每次在隔离分支或独立副本中引入一个缺陷，保存确切 diff，记录失败的测试及原因。如果测试没有发现缺陷，补充相应输入和断言，再对同一缺陷执行测试。需要确认失败确实由预期行为错误引起，例如编译失败不能算作测试发现了页内 ID 混淆。完成实验后恢复正确实现。

### 6. 核实、修复并回归

对每项确认的问题，保存最小复现输入，说明影响，完成修复并记录回归命令。如果没有在自己的产品中发现缺陷，使用上述实验练习复现、修复和验证过程。先运行与修复相关的测试，再运行前几周的共同案例和构建。

## 提交内容

提交新增测试、输入限制和安全处理代码。在 `course-notes/HW6.md` 中整理测试矩阵、最小复现、三项缺陷实验及修复后的回归结果，通过本周 PR 合并。大型临时输入留在本地，报告中记录生成方式。

## 完成标准

- 四层测试各有明确职责，五种性质由实际断言验证。
- 上限内和超限输入均有明确结果，文件不会被意外覆盖。
- 文本显示安全，DTD 不产生外部访问。
- 每个修复对应复现与回归，临时缺陷未进入正常交付。
- 自动化测试通过与浏览器实际观察分别记录。
