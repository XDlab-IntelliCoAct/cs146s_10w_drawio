# HW8：完成图表检查的产品工作流

**安排：W8。** 从 HW7 确定的候选版本继续，在 `hw08/workflow` 分支开发。学习顺序见[W8](../weeks/week08.md)。

## 本次作业要解决的问题

用户需要在同一个画图界面中完成检查、定位、修改、重查、比较和导出。本周将此前的检查核心集成为正式面板，并连接画布操作与现有 AI 对话。实现重点包括：让用户找到问题所在，清楚地知道结果是否适用于当前图表，以及修改后怎样确认问题已经解决。

## 实现步骤

### 1. 设计流程、草图与状态表

先编写简短的产品需求说明（PRD），说明使用者、核心任务、本次实现范围、成功场景和完成条件。再绘制界面草图，安排检查入口、范围与配置选择、结果摘要、问题列表、详情和导出操作。草图应能演示用户从发现问题到确认修改的顺序。

为画布未就绪、空图、待检查、运行中、检查完成且无问题、检查完成且有问题、执行失败和结果过期分别写出触发条件、界面显示及可用操作。空图可以成功完成检查，执行失败则没有可用结论；两者应有不同提示。检查完成但没有问题时，也需要明确反馈。

### 2. 接入工作区与共享核心

按[源码导航](../docs/source-map.md)阅读 `ChatPanel`、`DiagramProvider` 和 canvas store，了解工作区组件怎样取得图表数据。然后将 HW3 的最小检查界面扩展为工作区中的正式面板。

界面支持选择检查当前页或全部页面，使用 `flowchart`、`sketch` 或自定义配置。调用 HW4 的检查核心生成报告，核对与 CLI 的问题和统计一致。界面沿用项目现有组件与国际化词典，新增文字同步到英语、简体中文、繁体中文和日语词典。

### 3. 实现问题定位

用户点击问题时，先根据 `pageId` 和 `cellId` 确认目标仍然存在，再调用 `selectPage` 切换页面，并使相关图元在画布中可见。分别验证高亮、选择和滚动定位的效果；现有方法缺少必要能力时，增加小型桥接适配器。

多页中存在相同 `cellId` 时，仍应定位到问题所属页面。如果页面或图元已删除，提示重新检查；同源画布桥接不可用时，显示页面和图元 ID，保留检查与导出功能。

### 4. 实现异步状态与结果有效性

每次开始检查时，保存 `taskId`、文档会话、输入 `fingerprint`、`scope` 和配置，用来确定结果属于哪次操作。构造延迟测试：A 先开始，B 后开始，但 B 先完成、A 后完成。界面最终应保留 B 的结果，迟到的 A 不能覆盖它。

报告中的 `status` 表示检查是否成功执行，界面状态还需要表示任务正在运行或结果已经过期。保留原始报告及输入快照，在界面中用 `stale` 表达过期状态；用户导出的仍是那一次检查的完整报告。

用户在检查期间编辑图表、接收 AI 流式修改、恢复版本或切换文档时，需要重新核对输入快照。如果当前图表已不同于被检查的内容，将旧结果标记为过期。离开会话后，原任务不能继续更新旧界面。检查范围为 `all` 时，仅切换同一文档的页面不会改变内容，报告仍然有效。

将检查执行方法作为可替换接口，使测试能够指定延迟、失败和取消的结果。生产环境默认调用真实检查核心，故障模式关闭。

### 5. 接入两种修改方式

支持用户手工修改图表后重新检查。同时提供“交给 AI 处理”操作，将所选问题、页面与图元标识及相关快照信息填写到现有对话输入框，显示待发送内容，由用户确认后发送。

此步骤使用应用里的画图模型。先在模型设置中检查一次连通性，再用一份小图验证对话修改；编写代码的 Coding Agent 继续在自己的开发工具中使用。

发送消息、接收流式修改和恢复版本继续使用项目已有流程。传递图表文字时，将它作为数据转义和组织，防止标签中的指令被当成用户任务。AI 修改结束后提示重新检查，并比较修改前后的问题。

### 6. 提供报告使用与导出

问题列表支持按页面、规则和严重程度筛选，同时显示本次总览及相较上次的变化。筛选只改变当前显示的列表；导出时仍包含这次检查的完整报告。

导出内容应对应报告生成时的快照和配置。用户导出过期结果时，需要知道它描述的是旧版本图表。报告比较继续遵守 `scope`、配置和报告版本的约定。

### 7. 自动化与实际交互走查

复用项目 E2E 辅助工具，使用固定图表和模型响应替身自动验证：

- multi-page 导入、检查、跳页、定位、补名、重查、导出；
- 删除目标、版本恢复和切换文档；
- 连续检查、中途编辑、迟到结果与取消；
- 键盘、焦点、窄窗口、长标签和安全文本；
- 原有聊天、导入导出及版本流程。

在产品根目录按实际测试文件运行 Playwright，必要时先执行 `npx playwright install chromium`；最后运行类型检查、相关测试和构建。另进行一次真实模型修改走查，保存用户确认、实际修改和重查结果。

先运行 `npm run test -- --run` 与 `npm run check`，再执行 `npx playwright test` 并指定本周测试文件路径。Playwright 配置会启动所需服务，单独运行测试前应确认端口没有被已有实例占用。测试失败时保留 trace，或保存浏览器控制台中对应 `taskId` 的事件。

## 完成标准

- 用户可独立完成完整流程。
- 定位与结果对应相同文档，过期和失败可辨识。
- CLI 与界面报告一致，筛选不删导出数据。
- AI 操作经用户确认，旧结果不覆盖新结果。
- 测试替身能够稳定构造故障，生产环境默认使用真实实现，原有使用流程正常。
