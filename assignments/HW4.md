# HW4：设计可扩展的检查系统并完成任务交接

**安排：W4。** 先将 HW3 的代码合并到个人产品仓库的 `course/main`，再从该分支创建 `hw04/rules-and-report`。学习顺序见[W4](../weeks/week04.md)。

## 本次作业要解决的问题

正式流程图通常要求连接两端都有明确对象，而草图可以保留自由端点。因此，检查结果需要由规则配置决定。本周在 HW3 名称检查的基础上增加连接规则、多页处理和配置选择，生成能够说明问题位置的统一报告。

这些能力还将在终端和浏览器中使用。你需要将图表转换、规则执行和报告生成分开，定义模块之间交换的数据，并通过一次新会话任务交接检验设计是否明确。

## 实现步骤

### 1. 设计模块与数据接口

先画出模块依赖图，说明 XML 解析与规范化、页面和图元数据转换、规则执行、报告汇总以及界面展示分别由哪个模块负责。为模块之间的每个接口列出正常输入、空输入和失败时的结果。这样可以分别测试各部分，也能在接口变化时找到受影响的调用者。

检查核心接收由页面、节点和连接组成的数据对象，根据配置返回结果；它不直接读取 React 状态，也不修改传入的数据。Node 程序与浏览器分别取得输入、完成数据转换后，再调用同一核心。阅读项目的压缩页面处理逻辑时，注意保留错误引用，因为这些引用正是后续规则要检查的内容。

浏览器中的 `DOMParser`、`XMLSerializer` 和 React 上下文不能直接用于 Node。你可以选择两种环境都支持的解析库，或将依赖运行环境的操作放在各自的适配模块中。先在两端传入同一个页面与图元数据对象，确认规则结果一致，再分别测试 XML 解析。项目依赖中已有 `saxes` 可供使用，具体模块设计需要根据调用关系决定。

### 2. 实现四项规则

按照[共同规则](../docs/contracts.md)，实现 `missing-label`、`isolated-step`、`missing-endpoint` 和 `dangling-endpoint`。分别测试容器中的步骤、自连接、自由端点、跨页重复 ID、空页面，以及由 `object` 或 `UserObject` 包装的图元。

先手工画一份小图，按规则逐项判断。说明哪些图元作为流程步骤参与检查，怎样根据连接引用判断步骤是否孤立，以及同一图元为何可能同时触发两条规则。

### 3. 实现两种配置

实现 `flowchart` 和 `sketch` 两份完整配置。用同一份 `free-endpoint` 图表验证：流程图配置报告缺少端点的警告，草图配置关闭这条规则；两种配置都将指向不存在节点的引用报告为错误。

按照共同格式校验自定义配置，遇到未知规则或无效值时返回具体错误。再编写一份调整严重程度的配置，验证相应问题的级别和报告统计都随之改变。

### 4. 形成报告 v1

按[报告约定](../docs/contracts.md)实现 v1 报告，记录输入摘要、检查范围、配置、执行状态、问题列表、统计、错误和生成时间。使用 `pageId`、`cellId` 和 `ruleId` 共同识别一项问题，并按这三个字段稳定排序，使重复检查和后续报告比较能够得到一致结果。

对同一输入连续检查时，除生成时间外，结果应保持一致。有效空图可以成功完成检查；解析失败时无法得知问题数量，统计值应表示未知。对多页文件分别检查当前页和全部页，核对统计是否只覆盖选中的范围。

在 HW3 的开发环境检查按钮旁增加范围和配置选择，并显示报告摘要，以便从界面验证新增行为。参照[报告样例](../docs/contracts.md)核对成功与失败字段；更新原有名称检查测试，使它们继续验证扩展后的报告。

### 5. 完成一次新会话任务交接

将开发工作拆为数据适配、规则执行和报告生成三项任务，分别说明依赖、输入输出、样例和完成条件。选取其中一项，在新的 Agent 会话中继续开发。接收方先依据材料复述任务目标和接口，再开始修改代码。

新会话不依赖旧聊天上下文。观察它在哪些地方误解接口，修改交接材料后继续。可并行使用多个 Agent，也可按顺序换会话，均需保留交接和集成结果。

### 6. 处理集成问题并回归

集成时，用测试替身返回一项不符合接口约定的结果，例如将执行失败时的未知计数填为 0。检查哪条断言能够发现错误，再回看交接材料是否说明了失败结果的含义。这个练习用于检验模块之间的约定是否真正得到验证。

使用 `normal`、`labels`、`free-endpoint`、`dangling`、`multi-page`、`grouped`、`empty`、`compressed` 和无效输入完成集成测试，再重新验证 HW3 的按钮和结果列表。

## 完成标准

- Node 与浏览器共用核心，输入内容不变。
- 规则分别可测，组合报告与统计一致。
- 同一图元 ID 可以跨页出现，单页重复 ID 明确失败。
- 配置能够改变规则行为；报告明确区分执行失败和检查完成但没有问题。
- 接收方能依据交接材料继续任务，集成通过共同案例。
