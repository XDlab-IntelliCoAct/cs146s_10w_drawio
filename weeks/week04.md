# W4：模块接口与 Agent 任务交接

HW3 已经能够找出缺少名称的步骤。本周在此基础上增加连接规则、多页检查和不同配置，并将这些功能组织成可以由浏览器和 Node 程序共同使用的检查核心。开发过程中，还需要让一个新的 Agent 会话接续其中一项任务。

## 确定模块职责和数据接口

将 HW3 代码合并到个人开发主分支后，重新运行名称检查，确认功能仍然正常。再区分解析、规则和界面的职责，设计它们之间传递的数据。阅读[共同约定](../docs/contracts.md)中的产品输入、规则和报告三节，核对设计需要满足的行为。

浏览器提供 `DOMParser`，Node 运行环境没有浏览器 DOM，因此直接搬用浏览器解析代码可能无法运行。可以选择两端都适用的 XML 库，也可以分别完成解析，再将统一的数据对象交给检查核心。相关文件见[源码导航](../docs/source-map.md)。

## 用新会话检验接口说明

先用一个小函数练习：`countItems` 接收数组或 `null`，输入数组时返回元素数量，输入 `null` 时返回“未知”。写出接口说明和三个输入输出样例，交给新会话编写调用代码。观察它能否区分空数组与未知数量，再用同样的方法交接本周的模块任务。

阅读[管理 Agent 开发任务](../materials/slides/week04-1013-agent-manager.pptx)和 [Boris Cherny 演讲](../materials/slides/week04-1017-boris-cherny.pptx)，准备[任务上下文](../materials/templates/agent-context.md)。

## 实现并集成

按 [HW4](../assignments/HW4.md)完成规则、两种配置、报告 v1 和新会话交接。在开发环境的检查界面中增加范围和配置选择，用它验证模块组合后的行为；正式面板布局在 HW8 完成。

完成后，Node 与浏览器应能调用同一检查核心，得到字段和错误含义一致的报告。保存模块测试和交接材料；下一周将使用这些接口开发 CLI。
