# 教学准备与维护

从[固定教学提交](baseline.md)创建试做分支，按学生的学习顺序完成八次作业和最后两周实践。保存实际代码、命令、输入与观察结果，核对每周所需的代码和材料能否由前一周提供。

## 开课前准备

1. 在 Node 24 与 Python 3.11+ 环境安装，核对固定源码文件和项目脚本。
2. 用课程建议标签完成小规模 Ollama 连通性、schema 与工具调用试验，再让学生按作业运行自己的完整实验。
3. 核对 W1 八项案例的 dev/eval；提醒评估前冻结版本。
4. 运行辅助工具测试、课程验证和 MCP 传输检查。
5. 试做 W3–W8 的规则、报告、CLI、界面和状态；填写[共同场景](acceptance.md)的结果。
6. 确认个人 fork 的 Actions 可以运行，正常与失败 PR 的 base 都是学生 fork。
7. 准备测试替身、故障边界和性能输入；生产默认关闭注入。
8. 安排 W10 交叉试用和反馈回访。

W1/W2 使用学生自己的课程 fork，PR 合并到 practice/main；W3 起使用产品 fork，PR 合并到 course/main。讲解仓库切换时，让学生同时指出当前目录、origin 与目标分支。

## 课程仓库检查

在课程根目录：

```powershell
python tools/verify_course.py
python -m unittest discover -s tests -v
node --check materials/labs/review-candidate.mjs
```

安装 starters/hw02 的依赖后可运行：

```powershell
python tools/check_mcp_transport.py
```

这项命令验证传输骨架，起始工具的 NotImplementedError 会作为协议错误返回。学生完成后使用 starters/hw02/mcp_client.py 核对工具内容。

课件保存在 materials/slides，哈希记录在 slides.sha256.json。生成器提供人工输入；规则、Agent 循环、CLI 和界面是学生逐周完成的实现任务。

个人课程 fork 使用 python tools/verify_course.py --student-work，允许起始任务已经实现。课程工作流按仓库的 fork 标记选择此模式；教师仓库继续检查起始代码中保留学生任务。

## 各周准备与评价依据

| 周 | 教师提前检查 | 学生主要证据 |
|---|---|---|
| W1 | 模型标签、schema、记录字段和预览 | 批量数据、逐项含义判断与改进 |
| W2 | 文件适配、响应注入和 MCP | 控制测试、真实轨迹与完成判断 |
| W3 | 导入路径、角色与开发入口 | 需求、架构选择、浏览器与 PR |
| W4 | 多页、压缩、配置、报告 | 接口样例、交接和集成 |
| W5 | CLI 包装与 Actions | 退出码、文件、比较、两种 CI |
| W6 | 边界输入与缺陷注入 | 风险矩阵、性质、安全和回归 |
| W7 | 独立审查案例及需求 | 三轮核验、修复和交付判断 |
| W8 | 定位、迟到结果、版本恢复 | 状态表、E2E 与真实修改 |
| W9 | 生产构建、故障和计时 | 事件记录、故障恢复结果和性能对比数据 |
| W10 | 干净目录和试用安排 | 反馈迭代、交付与复盘 |

HW3–HW8 按功能与用户需求（35%）、设计与接口（20%）、验证与问题处理（25%）、Agent 使用及人工决策（20%）评分。W1 重点评价实验设计和结果判断，W2 重点评价执行控制和验证。W9、W10 沿用上述四个维度，分别考查运行恢复和根据反馈完成交付的情况。

## 维护材料

更新教学提交前重新检查源码导航和真实行为。保持学生正文围绕任务和操作，更新记录写入带日期的教师检查文件。

独立短变更的判定说明由教师单独保存，不放入学生公开仓库。教学准备记录见[verification.md](verification.md)；以实际执行结果填写模型、测试、构建和界面状态。

课程文字与导航的修改事项见[文档维护记录](reading-review.md)。该记录供教师维护时查阅。

视频的选择理由、核实方法和维护事项见[讲座视频维护记录](video-selection.md)。
