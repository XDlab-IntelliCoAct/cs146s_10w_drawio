# 课程学习路线

本课程围绕图表交付前的检查需求展开。前两周，你将使用本地模型生成图表规格，并编写一个能够读取、修改和复查图表的 Agent。从第三周开始，你将在 Next AI Draw.io 教学项目中开发图表检查功能，随后增加多页检查、命令行工具和检查面板。最后两周，你将运行完整产品，处理故障，并根据同学的试用反馈完成一次迭代。

前两周的代码和实验记录保存在个人课程仓库中。第三周开始，产品开发在另一个个人仓库中进行。下面先介绍两个仓库的用途，再说明各周作业之间的关系。

## 两个仓库分别用来做什么

**课程仓库 `cs146s-public`** 包含每周学习页、作业说明、课件和实验起始代码。第一周开始时，你需要在自己的 GitHub 账号下创建一份仓库副本，即 fork。HW1 和 HW2 的程序、测试及实验报告在这份副本中提交，通过拉取请求（PR）合并到自己的 `practice/main` 分支。

**产品仓库 `drawio-course-work`** 是 Next AI Draw.io 教学项目的个人 fork。第三周开始时，按[环境准备](setup.md)将它克隆到本地，从固定教学提交创建 `course/main` 分支。此后的功能代码、测试和报告都保存在这个仓库中，每周通过独立 PR 合并到自己的 `course/main`。下一周继续使用已经合并的代码。

两个仓库各有自己的 `.runtime/` 目录，用来保存本地运行结果。前两周的模型原始输出和练习文件放在课程仓库中；后续的检查报告、性能数据等放在产品仓库中。需要提交的实验结论写入作业报告，临时运行目录留在本机。

文档中的“仓库根目录”指该仓库最外层、包含 `README.md` 的文件夹。运行命令前，可以在 PowerShell 中执行 `Get-Location`，确认自己位于课程仓库还是产品仓库。

## 课程中几种模型和 Agent 的区别

W1、W2 使用本地 Ollama 模型。W1 的程序向模型发送提示并检查输出；W2 则由你编写 Agent 程序，让它接收模型提出的工具调用，检查参数，执行操作，再把结果交回模型。

W3 起使用的 Coding Agent 是帮助你阅读和修改代码的开发工具，在你自己的开发环境中配置。产品里的画图模型用于通过对话修改图表，在应用设置中另行配置；HW8 会把检查结果接入这一对话流程。

## 十周内容如何衔接

### W1–W2：理解模型输出与工具执行

W1 从自然语言流程描述出发，比较三种生成图表规格的方法。你需要分别判断输出格式、节点连接关系和需求含义，并保留实验程序、评估表和一份导出的图表。

W2 使用课程提供的 `practice.drawio`，先完成六个统一案例，再用 W1 自己生成的图表补充实验。你将实现读取、检查、修改和比较工具，编写控制循环，并记录模型请求、工具执行、文件变化和结束原因。这些记录用于解释模型的选择与程序的实际执行是否一致。

### W3–W4：在产品中实现并扩展检查功能

W3 从固定教学提交开始使用 TypeScript 开发。前两周学到的规格设计和验证方法继续用于分析需求；产品代码在本周重新实现。首先完成缺少步骤名称的检查，让用户可以点击按钮，查看问题所在的页面和图元。

W4 在名称检查的基础上增加连接规则、多页处理和配置选择。你需要把数据转换、规则执行和报告生成分成可以独立验证的模块，使 Node 程序和浏览器能够使用同一套检查逻辑。还要用新的 Agent 会话接续一项开发任务，检验接口和交接说明是否足够明确。

### W5–W7：自动化检查、系统测试与代码审查

W5 将 W4 的检查核心用于命令行工具，实现目录批量检查和报告比较，再在个人 fork 的 PR 中配置自动检查。这样，同一个功能既能由用户手动运行，也能进入开发者的日常工作流程。

W6 基于已有核心、CLI 和界面，设计分层测试，覆盖复杂图表、输入限制和文件安全。通过有控制地引入缺陷，检查测试是否能发现问题，并补充遗漏的验证。

W7 选取此前涉及多个模块的实际代码变更，分别审查行为、设计和可靠性。你需要逐项核实审查意见，修复确认的问题，完成回归测试，确定用于下一周界面开发的候选版本。

### W8–W10：完成用户流程并交付产品

W8 将已有检查能力做成工作区中的完整面板。用户可以筛选问题、切换页面并定位图元，修改后重新检查，再比较和导出报告。实现时还要处理连续检查、检查期间编辑和版本恢复，清楚地显示报告是否仍适用于当前图表。

W9 使用生产构建运行完整产品，记录检查过程，演练故障诊断与恢复，并根据测量结果完成一项性能优化。W10 邀请同学试用，将一项反馈转化为涉及多个模块或状态的修改，经过回归验证后，整理安装说明、运行手册和演示材料。

## 在什么情况下查阅参考文档

首次进行本地实验或进入产品开发时，按[环境准备](setup.md)安装本阶段需要的工具。每周的新概念在[概念导读](primer.md)中解释；开始实现数据和功能接口时，再查阅[共同约定](contracts.md)对应的章节。

W3 起，可以按[源码导航](source-map.md)中的问题阅读项目代码。[开发与提交](collaboration.md)说明分支、PR 和报告的位置；完成一项功能后，使用[共同检查场景](acceptance.md)核对它在程序、终端和界面中的行为。

## 示例程序与作业程序的运行顺序

课程提供的连通性检查、图表预览、练习文件准备和独立示例可以直接运行。`prompt_lab` 的批量实验、Agent 控制循环以及产品中的 `course:*` 命令，需要先完成相应作业中的实现。命令中的 `run_id`、用户名和文件路径应替换为自己的实际值。

如果程序抛出 `NotImplementedError`，说明执行到了尚未完成的学生任务。打开错误所指的函数，结合本周作业实现其中的 TODO。先用一个小案例检查结果，再运行整组实验。
